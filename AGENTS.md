# AGENTS.md

Working notes for AI coding agents in baskingspot/html.

## What this is

HTML in Zig, parsed the way the WHATWG HTML standard says: the tokenizer (§13.2.5) in `src/Tokenizer.zig`, tree construction (§13.2.6) and fragment parsing (§13.4) in `src/Parser.zig`, and the tree in `src/Document.zig`. It is incubating: unstable, with no promises about its API.

## Environment

Zig 0.16 only. The flake is the tool contract, from `baskingspot/nix`: `nix develop` provides Zig, `ziglint`, and the base tools, and nothing comes from the system PATH. The justfile is the command interface: `just test`, `just lint`, `just ci`. Run `just fmt` before you commit.

## Design

- The standard is the specification, not browsers and not other parsers. Read the current text at https://html.spec.whatwg.org/multipage/parsing.html before changing a state; it still changes, as processing instructions did in 2026.
- The tokenizer does no I/O and keeps no input it has consumed. `feed` takes bytes in any split, `next` returns null when it needs more, and splitting the input must never change a token or a parse error. The corpus test checks that by feeding every case one byte at a time.
- Every state is resumable: a state reads one character with `peek`, and nothing changes before it knows it has one. A state that looks ahead (`lookahead`, the named reference matcher) returns `.need_input` before consuming anything.
- Tree construction follows the standard's structure: one function per insertion mode, named for it, and the standard's names for its algorithms (`reconstruct`, `adoptionAgency`, `resetMode`, `appropriatePlace`). A rule that reprocesses a token returns `.reprocess`, and the dispatcher runs it again, foreign content check included.
- The parser runs no scripts and leaves out what only a browser needs: custom elements, declarative shadow roots, the sanitizer, form association. Keep those out unless a user needs one.
- `src/entities.zig` is generated by `tools/entities.py` from https://html.spec.whatwg.org/entities.json. Regenerate it; do not edit it.

## Tests

`test/html5lib-tests/` is vendored from `html5lib/html5lib-tests` and must not be edited to make a test pass; `THIRD_PARTY.md` records the commit. A case whose expectations contradict the standard or the rest of the corpus goes in `known_divergences` in `test/tokenizer.zig`, with the reason.

`test/wpt-tree-construction/` is vendored from web-platform-tests' `html/syntax/parsing/resources`, the same way, and `test/tree.zig` runs it with its own `known_divergences`. The tree construction tests live there now, not in html5lib-tests. The `scripted_*.dat` files are left out: they need a script engine.

## Rules

- Commit messages are one line, `area: summary`, and every commit is signed. Do not rewrite pushed history.
- Gate commands on their exit codes, and claim only what you ran.
- Format with `zig fmt` and lint with `ziglint`. `just fmt` and `just lint` run both.

## Changelog

`CHANGELOG.md` is one file, Keep a Changelog format, newest first. Add a bullet under `## [Unreleased]` in the same change that alters something a user can notice: the public API, expected behavior, performance a benchmark row would show, or the build requirements. Write from the user's side, and name the symbol or error.
