# AGENTS.md

Working notes for AI coding agents in baskingspot/html.

## What this is

HTML in Zig, parsed the way the WHATWG HTML standard says: the tokenizer (§13.2.5) in `src/Tokenizer.zig`, tree construction (§13.2.6) and fragment parsing (§13.4) in `src/Parser.zig`, and the tree in `src/Document.zig`. It is incubating: unstable, with no promises about its API.

## Environment

Zig 0.16 only. The flake is the tool contract, from `baskingspot/nix`: `nix develop` provides Zig, `ziglint`, the base tools, and the benchmarks' Go and Rust toolchains, and nothing comes from the system PATH. The justfile is the command interface: `just test`, `just lint`, `just ci`. Run `just fmt` before you commit.

## Design

- The standard is the specification, not browsers and not other parsers. Read the current text at https://html.spec.whatwg.org/multipage/parsing.html before changing a state; it still changes, as processing instructions did in 2026.
- The tokenizer does no I/O and keeps no input it has consumed. `feed` takes bytes in any split, `next` returns null when it needs more, and splitting the input must never change a token or a parse error. The corpus test checks that by feeding every case one byte at a time.
- Every state is resumable: a state reads one character with `peek`, and nothing changes before it knows it has one. A state that looks ahead (`lookahead`, the named reference matcher) returns `.need_input` before consuming anything.
- Tree construction follows the standard's structure: one function per insertion mode, named for it, and the standard's names for its algorithms (`reconstruct`, `adoptionAgency`, `resetMode`, `appropriatePlace`). A rule that reprocesses a token returns `.reprocess`, and the dispatcher runs it again, foreign content check included.
- The parser runs no scripts and leaves out what only a browser needs: custom elements, declarative shadow roots, the sanitizer, form association. Keep those out unless a user needs one.
- `src/entities.zig` is generated by `tools/entities.py` from https://html.spec.whatwg.org/entities.json. Regenerate it; do not edit it.

## Tests

`test/html5lib-tests/` is vendored from `html5lib/html5lib-tests` and must not be edited to make a test pass; `THIRD_PARTY.md` records the commit. A case whose expectations contradict the standard or the rest of the corpus goes in `known_divergences` in `test/tokenizer.zig`, with the reason.

`test/wpt-tree-construction/` is vendored from web-platform-tests' `html/syntax/parsing/resources`, the same way, and `test/tree.zig` runs it with its own `known_divergences`. The tree construction tests live there now, not in html5lib-tests. The `scripted_*.dat` files are left out: they need a script engine.

## Benchmarks

`bench/` compares this parser with Go's x/net/html and Rust's scraper (html5ever); `bench/README.md` is the method. Local numbers are for iterating, never claims. Keep the arms equivalent: `just bench-compare` refuses to be read until `check` shows the same trees, and a change to what one arm times changes the others or the README's table.

## Agent notes

Docs split by reader. `README.md`, `CHANGELOG.md`, `THIRD_PARTY.md`, and `bench/README.md` are for a person deciding whether and how to use the package. Agent material goes in `docs/slop/`: design notes such as `docs/slop/allocation.md`, and measurements in `docs/slop/results/<topic>-<yyyymmdd>.md`, with the method, the raw benchstat output, and what was tried and dropped. `AGENTS.md` and code comments may link `docs/slop/`; no human document links or names it.

## Rules

- Commit messages are one line, `area: summary`, and every commit is signed. Do not rewrite pushed history. A change made for a measurement adds a short body that names its `docs/slop/results/` file and gives the headline number.
- Gate commands on their exit codes, and claim only what you ran.
- `just fmt` formats Zig, Nix, Markdown, and the justfile; `just lint` checks them and lints the workflows with actionlint and zizmor.
- This repo's GitHub settings come from `baskingspot/.github`, with `just settings`. Do not change them by hand.
- To graduate the project, follow the `baskingspot-new-repo` skill: logos, a real README, and the audit passing.

## Changelog

`CHANGELOG.md` is one file, Keep a Changelog format, newest first. Add a bullet under `## [Unreleased]` in the same change that alters something a user can notice: the public API, expected behavior, performance a benchmark row would show, or the build requirements. Docs, CI, and internal refactors do not need one unless they change how someone uses the package. Write from the user's side, and name the symbol or error.

To release, dispatch the repo's `release.yml` with the version. The workflow moves the Unreleased section into a dated heading, sets `.version` in `build.zig.zon`, commits, tags, and opens the GitHub release. Do not tag by hand.
